# Developer Agent Documentation

## Overview
This document outlines how to collaborate with the developer agent, including expectations, workflows, and guidance for successful interactions.

## Workflow
1. The developer agent begins by examining the repository structure and relevant files.
2. The agent interprets the requirements document and any guidance from the product owner.
3. The agent formulates a concise plan, emphasizing only necessary files and changes.
4. The agent implements the changes, ensuring code quality and adherence to the existing conventions.
5. After completing implementation, the agent commits the work, pushes the branch, and opens a pull request.

## Expectations
- Use targeted exploration (list relevant directories and files only when needed). 
- Submit a written plan before editing files.
- Include only requested changes and avoid introducing unrelated modifications.
- Follow coding conventions already in place within the repository.
- Provide clear documentation, especially when new behaviors or processes are added.

## Product Owner Guidance
- Follow any specific directives from the owner, such as referencing key terms like "developer agent" when relevant.
- Ensure documentation references the collaborative nature of the agent and any specialized workflows.

## Maintenance Notes
- Keep documentation concise but informative.
- Update this document as the agent's role evolves or new processes emerge.
