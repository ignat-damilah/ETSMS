# Foundation Project Overview

This repository implements a simple foundation system consisting of API, application, domain, and infrastructure layers. It demonstrates a clean architecture style with minimal dependencies and a focus on maintainability.

## Repository Structure

- `Foundation.API/`: ASP.NET Core Web API exposing authentication-protected endpoints for employees, health checks, and observability metrics. Includes rate limiting, CORS, and Application Insights integration.
- `Foundation.Application/`: Application layer with DTOs, service interfaces, and implementations. Contains business logic to retrieve employee data via the repository infrastructure.
- `Foundation.Domain/`: Domain entities (e.g., `Employee`) and related invariants.
- `Foundation.Infrastructure/`: Infrastructure layer that wires EF Core, database context, and repository implementations.

## Building and Running

1. **Prerequisites**
   - .NET 8 SDK (matching `Foundation.sln`).
   - A configured PostgreSQL connection string named `FoundationDatabase` (used by EF Core in the infrastructure layer).
   - Application Insights configuration values if telemetry is required.

2. **Restore and Build**
   ```bash
   dotnet restore Foundation.sln
   dotnet build Foundation.sln
   ```

3. **Run the API**
   ```bash
   cd src/Foundation.API
   dotnet run
   ```

4. **Configuration**
   - `appsettings.json` should contain sections for `ConnectionStrings`, `Observability`, and `Authentication` (Azure AD settings with `Authority`, `Audience`).
   - `Observability` can optionally configure Application Insights instrumentation key and connection string.

## API Highlights

- Authentication via Azure AD with JWT bearer tokens.
- Authorization policies: `EmployeePolicy`, `LeadershipPolicy`, and `AdminPolicy`.
- Endpoints:
  - `GET /health/live` and `/health/ready` for basic liveness/ readiness probes.
  - `/health` exposes aggregated health check results.
  - `/metrics` for Prometheus-style instrumentation.
  - `/employees` endpoints secured by authorization policies, retrieving employee data.

## Development Notes

- Infrastructure dependencies are wired through extension methods in `Foundation.Infrastructure.Extensions.ServiceCollectionExtensions` and `Foundation.Application.Extensions.ServiceCollectionExtensions`.
- `EmployeeService` translates domain `Employee` instances into `EmployeeDto` for API consumption.
- The repository uses EF Core with tracking disabled for read operations and enforces ordering by last name / first name.
